I ran almost the same audit on my own Claude Code and Codex sessions and landed in the same place. In one week the agents wrote "done" or "tests pass" 948 times. A rule flagged 315 of those as having no test run after the last code change. When 46 of the flags were read with the full session open, 3 held up. The rest were tests the parser could not read, or claims about a document where a test run is the wrong proof. I also read 40 runs where the output showed failures but the exit code said 0 because of a pipe, and none of them was a hidden false green. So I agree with your framing: the agent checked, and the check left nothing a tool could read. One thing differed on my side. Codex hands the hook the command output with no exit code at all, so "did the test run" is a guess from the printed counts. How do you handle the 117 claims where a test ran before the claim but code changed after that run? That was where my 3 real cases came from.
